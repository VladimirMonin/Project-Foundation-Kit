# Project Foundation Kit

Переносимый методический комплект из десяти навыков для инженерных решений, программируемой архитектуры, проверки поведения, сопровождения знаний и проектирования интерфейсов. Дополнительные навыки помогают разобрать результат работы, инвентаризировать память и объяснять понятно. Не runtime framework и не оркестратор агентов; малые задачи остаются малыми.

Комплект не является приложением, не меняет файлы автоматически и не заменяет правила принимающего проекта. Версия: [0.4.0](VERSION). Основная лицензия: [MIT](LICENSE); для адаптации Caveman сохранены отдельные [условия и уведомления](pack/THIRD_PARTY_NOTICES.md).

## Быстрый старт

1. Скачайте репозиторий или клонируйте его:

   ```sh
   git clone https://github.com/VladimirMonin/Project-Foundation-Kit.git
   ```

2. Скопируйте всё содержимое [`pack/`](pack/README.md) в `tools/project-foundation/` своего проекта. Сохраняйте весь пакет, включая `LICENSE`, `UPSTREAM.md` и `THIRD_PARTY_NOTICES.md`, а не отдельный `SKILL.md`. Не переносите `.git`, тестовые проекты и рабочие окружения.
3. Передайте агенту запрос:

   ```text
   Прочитай действующие правила проекта, затем tools/project-foundation/README.md
   и tools/project-foundation/skills/pf-bootstrap/SKILL.md.
   Разверни достаточную основу, сохрани существующие правила и ручные дополнения.
   До записи назови конечный список создаваемых и изменяемых путей.
   Не выдумывай цели, архитектуру или проверенные команды.
   ```

Подключение: [Pi](pack/integrations/pi.md), [Hermes](pack/integrations/hermes.md), [обычное явное чтение](pack/integrations/generic.md). Глобальные настройки не требуются по умолчанию; обнаружение навыков зависит от клиента.

## Связанные проекты

- [Pi Agent Build](https://github.com/VladimirMonin/pi-agent-build) — version-pinned сборка Pi с профилями Code/Task, установщиком и guarded patches. Версии и область её приёмки принадлежат самой сборке.
- [pi-polza](https://github.com/VladimirMonin/pi-polza) — нативный динамический провайдер Polza AI для Pi с отдельным учётом реальных расходов в рублях.

Это ссылки на самостоятельные проекты, не устанавливаемые компоненты PFK. Комплект подключается отдельно полным `pack/` по инструкции выше; ссылка не устанавливает навыки, provider или профили автоматически.

### От скрипта к приложению — без дублирования правил

[Command-first](pack/references/architecture/command-first/README.md) помогает отделить прикладное ядро от оболочек: сначала достаточно CLI, позднее GUI или MCP используют тот же API. Общий код не означает общую живую сессию; дополнительные механизмы выбираются по требованиям, без обещания «никогда не переписывать».

[FigCraft](pack/skills/pf-ui-design/references/figcraft-handoff.md) — необязательный инструмент редактируемого дизайна и передачи в разработку. Сначала выбирается результат: визуальный эталон, конкретные переходы прототипа или настоящий интерфейс. Для Django есть [прямой маршрут](pack/skills/pf-ui-design/references/web-django.md), без обязательного перехода на React.

В пакет входят **13 полных исходных документов**: карта Command-first 00 и статьи 01–07, FigCraft I–III, workbook и указатель серии. Семь файлов добавлены, 00/01 заменены новыми предоставленными редакциями, четыре прежних оригинала не переписаны; все текущие снимки сохранены побайтно. Большие статьи читаются выборочно. Непоставленные исторические исследования отмечаются отдельно, не выдаются за проверенные ссылки.

## Содержимое

- [`pack/`](pack/README.md) — весь переносимый комплект: навыки, общие правила, формы, подключения и небольшой проверочный инструмент.
- [`docs/DESIGN.md`](docs/DESIGN.md) — устройство и границы комплекта.
- [`docs/SOURCE_NOTES.md`](docs/SOURCE_NOTES.md) — происхождение и первичные ссылки.
- [`docs/ACCEPTANCE.md`](docs/ACCEPTANCE.md) — проверки и их ограничения.
- [`tests/`](tests/README.md) — тесты проверочного инструмента и два синтетических проекта.
- [`AGENTS.md`](AGENTS.md) — правила разработки самого комплекта, не шаблон правил другого проекта.

[Минимальное внедрение](pack/references/minimal-adoption.md) может состоять из AGENTS и одного инженерного документа, без отдельного YAML-профиля. Формы — каталог, не обязательное дерево.

Формы включают основания проекта, рабочие инструкции, сценарии, планы, ADR, архитектуру, контракты, исследования, разборы ошибок, передачу работы, руководства, переводы и необязательные представления Obsidian. [Полный каталог](pack/README.md).

## Основные правила

Существующие правила и ручные дополнения сохраняются. Документы создаются по потребности, а не все сразу. Повторное применение без необходимого изменения не должно переписывать документы или даты. План не считается реализованной функцией, а корректный Markdown — доказательством работы продукта.

Общие источники правил: [жизненный цикл](pack/references/lifecycle.md), [метаданные](pack/references/metadata.md), [качество](pack/references/quality.md). Обновление универсального пакета не заменяет автоматически адаптации принимающего проекта.

## Проверка комплекта

Для проверочного инструмента нужен Python 3.10+ и PyYAML 6.0.3. Создайте отдельное окружение для инструментов и установите зависимости из [`pack/tools/requirements.txt`](pack/tools/requirements.txt). Подробный интерфейс и границы — в [инструкции инструмента](pack/tools/README.md).

Из корня репозитория, используя Python этого окружения:

```sh
python -I -B -m unittest discover -s tests -p 'test_*.py' -v
python -I -B pack/tools/check_foundation.py --pack
```

Проверки структуры не доказывают поведение агента, автоматическое подключение навыков или отрисовку Obsidian. Комплект можно использовать как обычные Markdown-файлы.
