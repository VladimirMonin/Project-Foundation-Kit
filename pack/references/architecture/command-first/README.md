# Command-first: короткий вход в полную серию

Прикладные операции и правила живут независимо от способа вызова. CLI, GUI и MCP —
адаптеры одного Application API, а не три реализации предметной логики. Это снижает
цену добавления оболочки, но не обещает отсутствие будущих изменений архитектуры.

- Для применения — [pf-command-first](../../../skills/pf-command-first/SKILL.md).
- Для карты тем и терминов — оригинальный [00_README](00_README.md).
- Зачем это нужно — [01 · введение](01_Command_First_Introduction.md).
- Границы и контракты — [02 · устройство](02_Command_First_Architecture_and_Contracts.md).
- Достаточная сложность A–D — [03 · выбор](03_Command_First_Architecture_Variants.md).
- Развёрнутый учебный проект — [04 · конвертер](04_Command_First_Image_Converter_Architecture.md),
  не готовое приложение и не обязательная схема каждого продукта.
- Живой GUI: идентичность, прогресс, ранняя отмена и окончание исполнителя —
  [05 · GUI и выполнение](05_Command_First_Live_GUI_Backend.md).
- Сохранение функций при миграции, происхождение параметров, принадлежность
  результата и последствия — [06 · смысл контракта](06_Command_First_Contracts_Compatibility_and_Effects.md).
- Достигнутый путь проверки, реальные байты CLI и конкретная поставка —
  [07 · проверка и передача](07_Command_First_Verification_and_Delivery.md).

Не загружайте всю серию для каждой задачи: выберите нужный раздел по карте.
Восемь исходных файлов (карта 00 и статьи 01–07) сохранены побайтно, включая имена,
YAML, примеры и Obsidian-ссылки. Для 00/01 выбраны новые предоставленные редакции;
02–04 не переписаны, 05–07 добавлены целиком. Прежние редакции остаются в Git-истории.
Вне Obsidian пользуйтесь обычными Markdown-переходами; отрисовка wiki-ссылок не обещана.
Это библиотека знаний, не автоматически принятая архитектура принимающего проекта.
Редакция, контрольные суммы и происхождение — в [UPSTREAM](../../../UPSTREAM.md).

## Как читать ранний пример и продолжение

Таблица статьи 04 с формулировкой о сохранении исходника — исторический пример,
не гарантия после начавшегося удаления. В статье 06 читай разделы
«Неподтверждённое удаление нельзя назвать сохранностью» и
«Уточнение к формулировке о сохранении исходника»: известный опубликованный файл
остаётся результатом, судьба источника может быть неизвестна. Нужна разрешённая
сверка конкретного последствия, а не слепой повтор всей операции.

## Непоставленные первичные исследования

Оригиналы 05–07 ссылаются на исторические отчёты, не входящие в публичный комплект:

| Статья | Отсутствующие основания |
|---|---|
| 05 | `COMMAND_FIRST_PRACTICE.md`, `01-core-cli-and-command-first.md`, `02-design-to-code.md`, `01-command-first-and-scope.md` |
| 06 | `COMMAND_FIRST_PRACTICE.md`, `01-core-cli-and-command-first.md`, `01-command-first-and-architecture.md`, `01-command-first-and-scope.md` |
| 07 | Все пять названных отчётов |

Нужные случаи изложены в самих статьях; это не новые независимые испытания.
Сырые отчёты не публикуются, заглушки под их именами не создаются. Только точные
исторические пары в неизменённых снимках получают `link.source_not_shipped`
уровня `not_checked` при `--pack`; отсутствующий источник не объявляется
проверенным. Остальные сломанные ссылки и границы проверяются обычно.
Область исключения и отказные контроли принадлежат
[контракту инструмента](../../../tools/README.md), не этой библиографической рамке.
