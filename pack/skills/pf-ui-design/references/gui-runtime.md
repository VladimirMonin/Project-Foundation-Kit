# Условный маршрут: GUI и реальное исполнение

Читать с [UI-навыком](../SKILL.md) **только** при затронутой длительной работе,
подписке, отмене, позднем ответе или закрытии. Для визуального каталога это выбор
состояний и правил, не обязанность реализовать runtime в макете. Для обычной подписи
маршрут не нужен. Прикладной контракт и owner проекта остаются каноном; здесь нет
новых DTO, менеджера задач, обязательной очереди, IPC или второго источника статуса.

Читать выбранные разделы CF05, а не всю серию. Статья сохраняет исторические примеры;
упомянутое в ней выполнение не является свежей проверкой принимающего проекта.

У операции, наблюдателя и представления могут быть разные исходы. Ошибка подписки
не доказывает неуспех уже выполненной работы. Вызов, сообщивший `started`, сам по себе
не доказывает, что event loop применил состояние и показал кадр. Пассивное чтение
статуса также не следует путать с активной проверкой, способной выполнить внешнюю
работу: [CF05 — чтение и проверка готовности](../../../references/architecture/command-first/05_Command_First_Live_GUI_Backend.md#passive-state).

## Различающие случаи, выбираемые по риску

- Первый элемент уже завершён, второй ещё удерживается в работе: показать известный
  итог первого и честный прогресс до общего terminal, а не проверять только финал.
- Запущен A, затем B, B завершился, приходит поздний A: при принятой latest-wins
  политике A не заменяет B **у владельца общего результата**, не только в виджете.
  Текущий B должен успешно применяться. Для независимых экспортов обе работы
  действительны: новое намерение не отменяет старое автоматически.
- Stop или close пришёл до handle: сохранены намерение и owner позднего ответа;
  скрытая карточка не считается остановленной работой. Потеря ответа на Start
  требует сверки по контракту, а не слепого повторного запуска.
- `result_ready` пришёл до cleanup: полезный результат сохранён, worker не уничтожен
  преждевременно. Для пула ждать свою работу и ресурсы, не смерть общего потока;
  фильтр старого UI-ответа не должен пропустить освобождение его исполнителя.
- Наблюдатель/форматирование упало после полезного эффекта: отдельно отразить проблему
  наблюдения, сохранить известный результат и сверить его у owner-а. Не повторять
  всю операцию автоматически. [CF05 — проекция](../../../references/architecture/command-first/05_Command_First_Live_GUI_Backend.md#projection),
  [неполный исход](../../../references/architecture/command-first/05_Command_First_Live_GUI_Backend.md#outcomes).

Нехватка надёжной identity активного элемента не разрешает угадывать его по индексу
строки. Передать узкий gap владельцу; не переписывать ядро ради визуального факта.
Реальная семантика retry, сохранения и неизвестных эффектов принадлежит контракту.

## Проверка и остановка

Это конечный выбор рисков, не декартово произведение всех флагов. При реализации
проверить реальных owner/consumer и промежуточные точки, следующую допустимую операцию
после отказа, закрытие и собственный cleanup; подменённый внешний край назвать явно.
Source, render, действие и предметный исход не заменяют друг друга. По
[quality](../../../references/quality.md) записать редакцию, условия, достигнутую ветку,
наблюдение и остаток: обязательное NOT_RUN, вне объёма и не достигнуто — разные вещи.
Новый review-контур, общий logger или продукт для проверки этой справки не нужны.
