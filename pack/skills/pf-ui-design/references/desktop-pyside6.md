# Приложение: desktop / PySide6

Читать только для desktop-задачи с [UI-навыком](../SKILL.md). Это самостоятельная
платформенная адаптация PFK, не готовый Qt-навык ECC. Web evidence не native proof.

## Окно, масштаб и клавиатура

Найти принятые widgets/actions/theme/tokens и layout. Выбрать из требований размеры
окна/минимальный размер, панели, длинные подписи и существенные scale/DPR условия.
Qt использует device-independent coordinates; geometry и raw image pixels не одно
и то же. Browser viewport не описывает native среду. В наблюдении указать целевую
ОС, редакцию приложения, window geometry и существенный scale/DPR, не полный env dump.
Первичный справочник: [Qt High DPI](https://doc.qt.io/qt-6/highdpi.html).

Не считать запрошенный `resize` фактическим размером. Сопоставить запрос → реально
выделенную область окна → внутренний viewport → ограничения/sizeHint/sizePolicy →
геометрию детей после layout → видимое содержимое. Внешняя рамка, клиентская область
и viewport прокрутки различаются; порог компоновки проверяется в своей области.
Stretch не обещает точную долю ширины независимо от ограничений. Не увеличивать окно
только для сокрытия обязательного узкого случая. Единицы шрифта (pt либо px) и база
пользовательского масштаба устанавливаются отдельно; одинаковое число не означает
одинаковую типографику. [Часть II: геометрия](../../../references/ui/figcraft/FigCraft_Practice_Part_2_RU.md#кейс-a-геометрия-измерять-интерфейс-а-не-угадывать-по-числам-).

Проверить доступность главного действия после resize, wrap/scroll, tab order,
shortcuts, видимый focus, подписи и возврат focus после диалога по архитектуре
приложения. Использовать native actions/widgets; **не переносить ARIA в Qt**.
Screenshot не подтверждает keyboard и screen reader. Непроверенная accessibility
граница остаётся непроверенной; отсутствие инструмента не делает её неприменимой.

## Внутренние части настоящих контролов

При изменении темы/размеров проверить не только внешний прямоугольник:
- `QSpinBox`: области/стрелки увеличения и уменьшения, место для числа, крайние
  значения, disabled/focus и действительную область нажатия, включая края;
- `QComboBox`: поле, область раскрытия и стрелку, **открытый popup**, строки/выбор,
  прокрутку и окружающие поверхности в принятой теме;
- `QCheckBox`: индикатор, checked/unchecked и применимые disabled/focus-состояния,
  связь подписи с доступной областью активации.

Клавиатуру и нажатие проверить действием; видимая стрелка не доказывает hit area.
QSS subcontrols/pseudo-states не равны CSS/ARIA. Допустим штатный стиль целиком:
не требуется рисовать все контролы заново или вводить универсальный размер цели.
Существенно изменённая оболочка с базовыми внутренними элементами — отдельный риск.
Основание: [Часть II: анатомия контрола](../../../references/ui/figcraft/FigCraft_Practice_Part_2_RU.md#кейс-b-почему-аккуратное-поле-оказалось-неудобным-);
первичная [Qt Style Sheets Reference](https://doc.qt.io/qt-6/stylesheet-reference.html).
Для визуального заказа это эталоны и правила; native-действия нужны при заявлении
о реализации, не добавляются к макету автоматически.

## Операции и native lifecycle

Найти существующий operation owner и настоящий путь signals/slots. QWidget обновляется
только в GUI/main thread. Учесть QObject affinity, queued delivery и lifetime;
успешный import не доказывает безопасное соединение worker → UI. Первичный источник:
[Qt for Python — Threads and QObjects](https://doc.qt.io/qtforpython-6/overviews/qtdoc-threads-qobject.html).
Документация Qt здесь только ссылка/собственное изложение, не включённый GFDL payload.

Для затронутой длительной операции применить [общий runtime-маршрут](gui-runtime.md).
В Qt отдельно подтвердить реальную доставку signals/slots в живой GUI-поток, доступность
Stop и отсутствие обновления уничтоженного widget при закрытии.

`result_ready`, окончание исполнения и освобождение ресурсов — разные границы.
У выделенного worker удерживать нужные ссылки/ресурсы до его действительного завершения
по принятому lifecycle; у постоянного пула ждать свою работу и её ресурсы, не смерти
общего потока после каждого задания. Не блокировать GUI неограниченным ожиданием и
не подменять кооперативный Stop принудительным `terminate()`.
Основание: [CF05 — завершение](../../../references/architecture/command-first/05_Command_First_Live_GUI_Backend.md#finish)
и [закрытие](../../../references/architecture/command-first/05_Command_First_Live_GUI_Backend.md#shutdown).

Это выбор рисков задачи, не обязательный полный ресурсный audit для смены подписи.
Для детерминированного behavior-теста допустим synthetic источник внешних событий,
если настоящее применение результата/owner остаются subject. Он не доказывает внешний
сервис или native event loop, если они заменены.

## Доказательства и ограниченный выход

Разделить source (реальные owners/wiring), rendered (фактическое окно/условия),
interaction (resize/keyboard/focus/close/cancel), behavioral (результат/stale/readback).
HTML-макет может помочь проектированию, но не доказывает Qt-layout/диалоги/DPR.
Mock, импорт модуля и screenshot не заменяют native lifecycle/actions.

Если заказан визуальный эталон, нужны редактируемая структура и фактический рендер
макета, не запуск Qt-приложения. Когда native-путь входит в заказ, без готового
разрешённого GUI-входа дать полезный source/design результат и назвать native/rendered/
interaction приложения NOT_RUN, конкретный сценарий и условия следующей проверки.
Для визуального заказа незаказанное исполнение приложения — вне объёма, не NOT_RUN.
Не устанавливать Qt или demo-продукт и не запускать частное приложение ради отчёта.
Приватность/cleanup принадлежат [quality](../../../references/quality.md), не второму
журналу UI. Адаптация и первичные references — [UPSTREAM](../../../UPSTREAM.md).
