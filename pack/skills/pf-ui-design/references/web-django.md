# Приложение: web / Django

Читать только для подтверждённой Django-поверхности вместе с [UI-навыком](../SKILL.md).
Это ограниченная адаптация UI, не установка Django, генератор сайта, backend-миграция
или рецепт развёртывания. Сначала выбрать результат: визуальный эталон, перечисленный
прототип либо настоящий интерфейс. Платформенные проверки не повышают глубину заказа.

Технический справочник ниже — официальная документация **Django 6.0**, не указание
обновить проект. При применении сверить фактическую версию и её документацию.
Не считать Django backend доказательством Django Templates: возможны другой шаблонный
backend и отдельный frontend. Для React frontend читать [React-маршрут](web-react.md)
только в его области. Подтверждённому Templates-проекту не навязывать React, Next.js,
DRF, HTMX, SPA, WebSocket или очередь задач. Bootstrap не обязателен: использовать
лишь уже принятый или отдельно выбранный способ оформления.

## Карта одной затронутой поверхности

Найти действующий URL/view, template backend и его версию, base/blocks/includes,
форму и widgets, значимые context-поля и их владельцев, CSS/JS/SVG, локаль и тему.
Проверить реальные пути вызова, не только похожие имена файлов. Различать current,
требование и proposed; не изобретать отсутствующую форму или endpoint. Достаточна
карта страницы, а не аудит всего сайта. Ограничения доступа к исходникам сохраняются.

В визуальном заказе передать редактируемую композицию, правильные тексты, значимые
состояния и правила размеров. Ошибка поля, общая ошибка формы, отказ в действии,
сохранённый ввод, положительный исход и длинная подпись — кандидаты по сценарию,
не обязательная квота экранов. Данные примера помечать демонстрационными. Проверить
структуру и фактический рендер макета; backend-run и все клики прототипа вне такого
объёма. Отсутствующий обязательный рендер остаётся NOT_RUN.

## Шаблоны и контекст, не копия экспорта

Сопоставить область макета с существующим шаблоном/компонентом. В DTL сохранить
принятые `extends`, `block`, `include`, контекст view/context processors и текущие
URL-связи. Для другого backend использовать его синтаксис, не смешивать DTL и Jinja2.
HTML/TSX FigCraft — исходный материал для адаптации, не готовый Django template.
Сырые экспорты, нормализованные токены и поддерживаемый код хранить раздельно.

Не заменять динамические значения нарисованными числами, не терять условия
видимости, пустое/ошибку и реальные права. Сохранять принятую HTML-семантику:
действие — button, переход — ссылка, поле связано с label, ошибка с полем и способом
исправления. Не отключать HTML escaping и не добавлять `safe` к пользовательскому
содержимому ради совпадения с макетом. Фокус, клавиатура и модальность требуют
действий в браузере, не только проверки HTML-строки.

## Форма: GET → invalid POST → valid POST

Сохранить реальный `Form`/`ModelForm`, его fields/widgets и серверную валидацию.
Подготовка данных, проверка и HTML-отрисовка — разные части. Перестановка полей не
разрешает менять предметную семантику, имена отправляемых полей, правила сохранения
или область авторизации. Сохранять применимые hidden-поля, prefixes и management
данные formset-а, если он действительно используется.

- **GET:** нужная форма и initial/context по текущему контракту; чтение не становится
  записью ради нового интерфейса.
- **Invalid POST:** повторно показать связанную с отправкой bound form, ошибки
  полей и `non_field_errors`, help text и допустимый повторный ввод. Не заменять её
  новой пустой формой. Секреты и файловые поля не заполнять повторно вопреки политике
  widget/безопасности; при необходимости объяснить повторный выбор.
- **Valid POST:** действующий обработчик проверяет `is_valid()` и использует
  `cleaned_data` по принятому сценарию; сообщение/redirect соответствуют настоящему
  исходу. Сам `Form.is_valid()` не выполняет сохранение и не доказывает эффект.
- При ручной разметке сохранить label/ID, widget, field errors, общие ошибки и
  скрытые поля; декоративная красная строка не заменяет ошибки реальной формы.

Необходимое новое предметное правило передать owner-у через [pf-plan](../../pf-plan/SKILL.md).
Дефицит одного UI-факта не основание переписывать ядро или вводить новый API-framework.

## Защита действия остаётся на сервере

Сохранить действующие проверки аутентификации, разрешений и доступа к конкретному
объекту. Скрытая/disabled-кнопка не запрещает прямой запрос; CSRF не заменяет
авторизацию, а вход в аккаунт сам по себе не означает право выполнить действие.
Проверить серверный отказ и отсутствие недопустимого эффекта по политике проекта.

Для внутренней POST-формы DTL сохранять `{% csrf_token %}` внутри `<form>` и
действующую серверную CSRF-защиту. Для другого backend использовать его механизм
(например, предусмотренный Django Jinja2 `csrf_input`), не буквальную копию DTL.
Не отключать middleware/защиту и не применять `csrf_exempt` ради демонстрации.
Токен не отправлять внешнему получателю. При уже выбранном AJAX учитывать настройки
получения токена и установленный same-origin-путь передачи, не изобретать новый.

## Assets, локализация и прогрессивное поведение

- Сохранить существующий static pipeline и namespaces ресурсов. Для принятого DTL
  использовать `static` tag, например с `{% load static %}`, а не абсолютные пути
  экспортного каталога. Если проект использует bundler/manifest, следовать ему,
  не добавлять второй pipeline. Наличие файла не доказывает его загрузку браузером.
  Шрифты/SVG, глифы, лицензии и фактические пути проверить в нужной среде.
- Переводы, plural/forms и форматы чисел/дат принадлежат каталогам и правилам сайта.
  В DTL использовать принятые i18n tags (`translate`/`blocktranslate`); не собирать
  предложения из фрагментов и не подменять каталоги языковыми режимами макета.
  Проверить длинные строки и RTL, если поддерживается. Тема и язык независимы.
  Qt-правило горячей смены языка не переносить на сайт автоматически: сохранить
  реальный договор сайта о выборе языка, навигации, значениях и перезагрузке.
- Дополнительный JavaScript вводить только по принятой потребности. Сохранить
  обещанный no-JS путь: отправку формы, ошибки и достижимость действий без скрипта.
  Наличие Django не доказывает, что no-JS уже обещан; отсутствие такого обещания
  не разрешает самовольно менять текущий договор. Для затронутой длительной работы,
  подписки или отмены читать [runtime-маршрут](gui-runtime.md), не для каждой формы.

## Учебный сценарий и достаточные проверки

Это **не выполненный эксперимент**: ограниченная форма редактирования материала.
Обычное состояние, invalid с сохранённым допустимым вводом, положительный исход и
длинная подпись в узкой области образуют конечный учебный набор. Визуальный заказ
заканчивается эталонами/правилами и их просмотром; прототип добавляет названные
переходы. Только при заказе реализации пройти существующую форму/view:

| Граница | Достаточное наблюдение по задаче | Не заменяет его |
|---|---|---|
| Template/context | Выбран нужный template, реальные context и bound form, сохранены условия/ошибки | Успешный import Django |
| Rendered | Реальная страница с загруженными assets, нужной локалью/темой и контрольной областью; длинный текст не скрывает действия | HTML-строка или один широкий кадр |
| Invalid / interaction | Отправка, связанная ошибка, допустимый ввод сохранён, исправление и клавиатурный путь доступны | Нарисованная ошибка в макете |
| Valid / behavior | Настоящий обработчик достиг операции и результат подтверждён по её контракту, отдельным чтением где нужно | Переключение экрана на «готово» |
| Forbidden / CSRF | Достигнут соответствующий серверный отказ; запрещённый эффект отсутствует | Скрытая кнопка или обычный route-test без CSRF enforcement |
| No-JS, если обещан | Сценарий выполнен без JavaScript, ошибки и следующее действие доступны | Наличие обычного `<form>` в исходнике |

Django test client по умолчанию ослабляет CSRF-проверки. Для проверки именно защиты
нужен предусмотренный режим, например `Client(enforce_csrf_checks=True)`, и достигнутая
ветка отказа; успешный обычный тест маршрута этого не доказывает. Команды брать из
реального проекта, не выдумывать `manage.py`-запуски по этой справке.

Разделить source/template/context, rendered, interaction и behavioral evidence по
[quality](../../../references/quality.md). Недоступный обязательный браузерный или
серверный путь — NOT_RUN с точным остатком; свойство вне выбранной глубины — вне
объёма с причиной; запущенная, но недостигнутая ветка — не PASS. Выход: ограниченная
дельта или дизайн, сохранённый продуктовый договор и передача по местной политике.
