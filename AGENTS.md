# Работа над Project Foundation Kit

Это набор методик, инструкций, шаблонов и небольших проверок, не приложение. Пользовательский результат — переносимый `pack/`.

## Контекст и границы

- Сначала прочитай README.md и docs/DESIGN.md, затем только относящиеся ресурсы.
- До записи проверь фактический корень, изменения и полномочия; назови конечный список путей. Не перезаписывай неизвестную работу.
- Один основной владелец каждого общего правила: pack/references/metadata.md, lifecycle.md, quality.md. Навыки и шаблоны ссылаются на них, не размножая схемы.
- В pack/ не входят машинные пути, личные данные, секреты, история сессий и частные ограничения исходных проектов. Сторонние наборы навыков не копируются; происхождение — в docs/SOURCE_NOTES.md.
- Native SKILL.md и AGENTS.md не обязаны иметь паспорт обычной заметки. Версия и дата навыка — строки внутри metadata. Шаблон и заполненный документ — разные роли.
- Не меняй глобальные навыки, профили, настройки клиентов или соседние проекты. Не запускай продукты, GUI и платные вызовы ради проверки Markdown. Не устанавливай зависимости без конкретной необходимости и разрешённой изоляции.

## Проверка и завершение

Проверяй точный изменённый маршрут, свойства, ссылки, пригодность формы и сохранность местных решений. Команды и ограничения checker-а принадлежат pack/tools/README.md, тестов — tests/README.md. Не выдумывай команды принимающего проекта.

Обнови затронутые знания либо обоснуй отсутствие влияния. Один независимый reviewer оценивает связный результат и риски; обязательное замечание возвращается автору. Не stage/commit без владения индексом и разрешения. Сохраняй только принятую дельту, без чужих изменений. Push, tag и release требуют отдельного разрешения.

Сообщай реальные результаты и NOT RUN. Не превращай необязательное улучшение в новый этап. Переносимый ZIP собирается из содержимого pack/, не всего checkout; pack/LICENSE должен сохраниться. Публичная лицензия комплекта — MIT.
